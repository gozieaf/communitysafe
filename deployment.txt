The following configurations are required: Show all steps

1) Backend API environment variables
Create a real backend environment file from .env.example, then fill in production values.

Example:
DATABASE_URL=postgresql+psycopg://geoapp:CHANGE_ME@HOST:PORT/geoapp?sslmode=verify-full
PGSSLROOTCERT=/run/secrets/aiven-ca.pem
JWT_SECRET=replace-with-a-random-32-byte-secret
CORS_ORIGINS=https://your-app.vercel.app
ACCESS_TOKEN_EXPIRE_MINUTES=15
REFRESH_TOKEN_EXPIRE_DAYS=7
UPLOAD_MAX_BYTES=52428800
COOKIE_SECURE=true
COOKIE_SAMESITE=none

Meaning of each value
DATABASE_URL
PostgreSQL URL for the Aiven/PostGIS database
must use sslmode=verify-full
PGSSLROOTCERT
path to the Aiven CA certificate file
used by the API to validate the database TLS certificate
JWT_SECRET
32+ random bytes, never commit this to Git
CORS_ORIGINS
production Vercel frontend origin only, e.g. https://geoapp.vercel.app
no trailing slash
COOKIE_SECURE
set to true in production
COOKIE_SAMESITE
set to none because frontend and API are on different domains
Keep all secrets in the backend host’s secret manager, not in GitHub or Vercel.

2) Set up the PostgreSQL/PostGIS service
Use Aiven or another managed PostgreSQL service:

Create a PostgreSQL service
Enable PostGIS
Create the application database and user
Download the CA certificate
Save the certificate in the runtime environment or secret store
Then use the DB credentials to fill:

DATABASE_URL
PGSSLROOTCERT

3) Deploy the backend API
The backend is not meant to run on Vercel. It should be deployed to:

Google Cloud Run, or
IBM Code Engine, or
another container runtime
Production backend deployment checklist
Set the environment variables above in the API host
Ensure the runtime image has GDAL/OGR installed
Run migrations:
alembic upgrade head
Run the foundation verification:
python scripts/verify_foundation.py
Confirm health check passes:
GET /health

4) Frontend Vercel environment variables
From .env.local.example, create the Vercel production variables:

NEXT_PUBLIC_API_URL=https://api.example.com
NEXT_PUBLIC_MAP_STYLE_URL=https://maps.example.com/style.json
NEXT_PUBLIC_WATSONX_INTEGRATION_ID=
NEXT_PUBLIC_WATSONX_REGION=
NEXT_PUBLIC_WATSONX_SERVICE_INSTANCE_ID=

Important
NEXT_PUBLIC_API_URL
the live backend API URL, not the local dev URL
NEXT_PUBLIC_MAP_STYLE_URL
the map style JSON endpoint
NEXT_PUBLIC_WATSONX_*
public chat integration identifiers only
not API credentials

5) Create the Vercel project
Follow the production runbook in github-vercel-production.md:

Import the GitHub repo
Set the root directory to frontend
Add the frontend environment variables above
Deploy
Set the custom domain
Update CORS_ORIGINS on the backend if the frontend domain changes

6) Final ordering
Use this sequence:

Provision PostGIS database
Fill backend env vars
Deploy backend API
Run migrations and health check
Add frontend env vars in Vercel
Deploy frontend
Verify:
signup/login
refresh tokens
admin upload
map loading
Watsonx widget loads
CORS is limited to intended origins

7) Security rule
Never commit:

database URL
CA certificate path or PEM content
JWT secret
production API URL in unsafe places
Keep those in:

backend secret manager
Vercel environment settings
deployment platform secrets
